# 增广栈：让每个版本携带可恢复摘要

普通栈只保存元素。若还要常数时间查询当前最小值、最大值、总和或其他前缀聚合，查询时扫描整个栈会重复计算同一段历史。更稳定的做法是：每压入一个值，就把加入该值后的摘要一起保存。

## 每一层都是一个完整版本

设第 $i$ 层保存值 $x_i$ 和前 $i$ 层的最小值

$$
m_i=\min(m_{i-1},x_i).
$$

压栈只读取上一层摘要并产生新层；弹栈删除最上层后，下一层保存的正是旧版本摘要。因此查询最小值只读栈顶，四种操作都为 $O(1)$。

这不是只针对最小值的技巧。若摘要运算满足“新摘要可由旧摘要与新元素常数合并”，就能同样维护：

- 最大值、和、按位与或、最大公约数；
- 最小值及其出现次数；
- 同时维护多个彼此独立的摘要。

空间仍为 $O(n)$，但每层记录从一个值扩展为一个小状态。

## 为什么弹栈不需要逆运算

直接只保存一个全局最小值时，弹出唯一最小元素后无法知道次小值；问题在于 `min` 没有可用的逆运算。逐层保存版本绕开了求逆：弹栈不是“从当前摘要减去一个元素”，而是直接回到上一版本。

这条边界可推广：

- 若聚合可逆，例如整数和，可以只保存全局摘要并在弹栈时撤销；
- 若聚合不可逆但可常数合并，就逐层保存摘要；
- 若需要查询栈内任意区间，只有前缀版本仍不够，应使用持久化线段树、树状数组或其他范围结构。

## 从栈迁移到队列

队列同时从一端加入、另一端删除，单个前缀摘要无法在删除队首后恢复。可以用两个增广栈实现：

- 输入栈负责新元素；
- 输出栈为空时，把输入栈逐个弹出并压入输出栈；
- 队列摘要由两个栈顶摘要合并。

每个元素至多在两个栈间搬运一次，因此操作均摊 $O(1)$。若摘要合并依赖顺序，两个栈要分别保存从栈底到栈顶与从栈顶到栈底的方向摘要。

## 持久化版本

把每个栈层实现为不可变节点 `(value, summary, previous)`，一次压栈只创建一个节点，弹栈返回 `previous`。任意历史栈顶都可作为版本根；各版本共享未修改后缀，单次更新、查询仍为 $O(1)$。

持久化要求旧节点不再被原地修改。若摘要本身包含可变容器，还要明确深拷贝、结构共享或引用计数，否则表面不可变的版本仍可能互相污染。

## 设计检查

1. 摘要能否由旧摘要与一个新元素常数合并？
2. 空栈时摘要和查询的契约是什么？
3. 重复最小值是否需要计数，还是逐层摘要已经自然处理？
4. 元素和摘要是否可能溢出原类型？
5. 需要的是栈顶前缀摘要，还是任意区间查询？
6. 若改成队列，摘要合并是否交换、是否依赖方向？
7. 若保留历史版本，任何共享对象是否仍可能被修改？
