# 单调队列：维护仍可能最优的窗口候选

滑动窗口最大值的朴素做法会在相邻窗口中反复扫描同一批元素。单调队列只保留“尚未过期、且未来仍可能成为答案”的下标。

## 两类永久淘汰

处理新位置 $i$ 时，对最大值队列执行：

1. 队首下标若小于等于 $i-k$，它已经离开窗口，永久删除；
2. 队尾值若不大于新值，队尾位置更早且值不更大，以后不可能优于新位置，永久删除；
3. 把 $i$ 加入队尾。

队列中的下标严格递增、对应值严格递减，因此队首始终是当前窗口最大值。

## 为什么总时间是线性

一个下标只会：

- 入队一次；
- 因过期从队首出队至多一次，或因被支配从队尾出队至多一次。

虽然某一轮可能连续弹出多个元素，但全部循环的弹出总数不超过 $n$，所以时间复杂度为 $O(n)$。这是摊还分析，不是每轮最坏 $O(1)$。

## 与堆的比较

最大堆也能维护窗口最大值，但过期元素通常需要惰性删除：

- 单调队列：$O(n)$，空间 $O(k)$，适合 FIFO 窗口和单一极值；
- 最大堆：$O(n\log n)$ 或 $O(n\log k)$，实现更通用，适合删除顺序不规则；
- 平衡树：$O(n\log k)$，能同时维护最小值、最大值、计数与前驱后继。

结构选择取决于删除顺序和需要维护的摘要，而不只是“要求最大值”。

## 从固定窗口到最短合法区间

若窗口左边界不是匀速移动，而是要寻找满足条件的最短区间，仍可能维护前缀状态的单调候选。LeetCode 862 中，递增前缀和值队列负责删除两类不可能更优的候选：

- 队首已经与当前前缀形成合法区间，继续保留只会得到更长答案；
- 新前缀和不大于队尾前缀和，且位置更晚，因此在未来同时拥有更大差值与更短长度。

## 易错检查

- 队列保存下标而不是只有数值，否则无法判断过期；
- 先删除过期元素，再读取队首；
- 相等值使用 `<=` 弹尾可保留更新的下标，窗口寿命更长；
- 只有窗口形成后才写答案；
- `k=1` 与 `k=n` 是否正确；
- 负数不会破坏固定窗口最大值，但会破坏许多依赖和单调性的双指针方法；
- 在线修改历史元素后，静态单调队列通常失效，需要区间树。
