# 搜索与枚举知识地图

搜索把“所有可能答案”组织成状态图或决策树。好的搜索不是把循环写成递归，而是先回答：

1. 一个状态包含哪些足以决定后续的信息；
2. 当前有哪些合法选择；
3. 哪些前缀已经不可能完成，可以立刻剪枝；
4. 修改状态后怎样无损恢复；
5. 输出规模是否已经决定复杂度下界。

## 总览

| 模型 | 状态 | 常见边 | 结束条件 |
| --- | --- | --- | --- |
| 回溯枚举 | 已确定前缀与剩余选择 | 做一个决策 | 前缀成为完整答案 |
| DFS | 当前节点与访问状态 | 沿一条边深入 | 子图处理完成 |
| BFS | 当前层状态 | 执行一次等价代价操作 | 第一次到达目标 |
| 双向搜索 | 两端边界集合 | 各扩展一层 | 两侧状态相交 |
| 迭代加深 | 当前深度上限 | 受限 DFS | 在最小可行深度命中 |

## 先算搜索树，再写剪枝

若每层有 $b$ 个选择、深度为 $d$，粗略状态数是 $b^d$。但输出全部排列时，本身就有 $n!$ 个答案；生成每个长度为 $n$ 的答案还需 $O(n)$，因此 $O(n\cdot n!)$ 已经达到输出下界。

剪枝只应删除不可能扩展成合法答案的状态。若剪枝条件依赖尚未处理的信息，就必须证明它是必要条件；凭直觉提前停止可能漏解。

## 回溯的最小接口

一轮递归通常遵循：

```text
检查是否得到完整答案
枚举当前合法选择
  做选择
  递归
  撤销选择
```

“撤销”不是形式动作，而是保证同层不同分支从同一个父状态出发。若使用不可变状态或值传递，可以不显式恢复，但会产生额外复制。

完整的合法前缀、原地交换、复杂度下界和重复元素处理见[回溯：只展开仍可能完成的前缀](backtracking.md)。

## 搜索与图遍历的边界

- 状态天然有重复到达路径时，应使用访问标记、最短距离或记忆化，避免把同一状态反复展开；
- 决策树中每条根到叶路径代表不同构造过程，贸然全局去重可能删掉合法答案；
- 所有边代价相同且只求最少步数时，BFS 比普通 DFS 更自然；
- 状态依赖形成 DAG 且只求计数或最值时，动态规划通常比逐路径枚举更合适；
- 能直接按字典序块计数并跳过时，应使用排名或逆排名，而不是生成前 $k-1$ 个答案。

## 建议掌握顺序

1. 子集、组合与排列回溯；
2. 有效括号等合法前缀剪枝；
3. 网格和图的 DFS / BFS；
4. 状态判重与最短步数；
5. 双向搜索、迭代加深与启发式搜索；
6. 计数、排名和第 $k$ 个答案之间的转换。
