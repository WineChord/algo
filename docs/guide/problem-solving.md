# 解题方法：从暴力到最优

面对陌生题目时，稳定的方法比偶然的灵感更可靠。本页给出一套可以反复执行的流程，目标是把“我怎么会想到”拆成可检查的推理步骤。

## 1. 把题目翻译成精确定义

先去掉故事背景，写下：

- 输入对象：数组、字符串、树、图、集合还是状态序列；
- 输出对象：可行性、计数、最值、构造方案还是第 $k$ 个答案；
- 允许的操作及其代价；
- 数据范围、值域、是否有序、是否允许重复；
- 单组还是多组测试，询问与修改是在线还是离线。

对每个模糊词追问。例如“子数组”必须连续，“子序列”保持相对顺序但不要求连续；混淆二者会直接改变模型。

## 2. 用约束筛选复杂度

粗略估算一秒内 $10^8$ 次简单运算是上限而不是保证。更实用的经验表见[复杂度分析](complexity.md)。先算目标复杂度，再选算法：

- $n\le 20$：考虑 $2^n$、折半搜索、状态压缩；
- $n\le 500$：常见 $O(n^3)$；
- $n\le 5000$：常见 $O(n^2)$；
- $n\le 2\times 10^5$：通常需要 $O(n\log n)$ 或 $O(n)$；
- $n$ 极大但值域或状态很小：转向数学、矩阵快速幂或按值域处理。

这些只是入口。常数、语言、内存访问、测试组数和操作类型都会改变实际边界。

## 3. 先得到最直接的正确解

暴力解有三重价值：

1. 暴露问题的完整选择空间；
2. 给优化提供准确的瓶颈；
3. 在随机对拍中充当可信的参照答案。

常见暴力枚举维度：

- 枚举答案；
- 枚举区间两端；
- 枚举子集、排列或路径；
- 枚举最后一步、分割点或父状态；
- 对每次询问重新计算。

写出复杂度时，不要只写最外层循环。例如枚举 $O(n^2)$ 个区间、每次 $O(n)$ 求和，总复杂度是 $O(n^3)$。

## 4. 对瓶颈做结构化提问

优化通常来自以下几类变化。

| 瓶颈 | 追问 | 常见工具 |
| --- | --- | --- |
| 相同信息反复计算 | 能否预处理或复用前一状态？ | 前缀和、记忆化、DP |
| 每次都扫描全部候选 | 候选是否有序或具有单调性？ | 二分、双指针、单调队列 |
| 频繁找最值或第 $k$ 小 | 能否动态维护顺序信息？ | 堆、平衡树、树状数组、线段树 |
| 枚举大量等价状态 | 状态中哪些信息对未来无用？ | 状态压缩、等价类、DP |
| 局部选择看似独立 | 能否证明一次局部选择可交换？ | 贪心 |
| 对象之间存在转移或连接 | 能否建成点和边？ | 图搜索、最短路、流 |
| 只关心答案是否可行 | 可行性是否随答案单调？ | 答案二分 |

!!! example "典型优化链"

    求多个静态区间和：逐个区间扫描是 $O(nq)$；发现每个询问都在重复累加后，预处理前缀和 $s_i=\sum_{j=1}^{i}a_j$，每次用 $s_r-s_{l-1}$ 回答，总复杂度降为 $O(n+q)$。

## 5. 明确不变量并证明正确

优化后的代码往往更短，但隐含假设更多。至少选择一种适合的证明方式。

### 循环不变量

适用于二分、双指针、数据结构维护。证明三件事：

1. 初始化前不变量成立；
2. 每次迭代保持成立；
3. 循环结束时，不变量加终止条件推出答案。

### 数学归纳

适用于递推、树和动态规划。证明规模更小的子问题正确，并说明转移覆盖所有情况且没有非法重复。

### 交换论证

适用于贪心。取任意一个最优解，证明可以把它的第一步换成贪心选择而不变差，再递归处理剩余部分。

### 反证法

假设算法给出的答案不是最优，利用最优解和算法选择之间的第一个分歧推出矛盾。

## 6. 实现前固定边界语义

许多错误不是算法错误，而是代码中的定义不断变化。

- 区间统一使用闭区间 $[l,r]$ 或半开区间 $[l,r)$；
- DP 状态明确“恰好”还是“至多”；
- 图的点编号统一从 $0$ 或 $1$ 开始；
- 不可达状态使用不会参与溢出运算的哨兵值；
- 乘法、累加和距离在计算前决定是否需要 `long long`。

推荐在草稿上先写一句不变量，再写循环。例如二分中的“答案始终位于 $[l,r)$”比背某一行 `mid` 更新更可靠。

## 7. 主动构造测试

不要只重复题目样例。至少覆盖：

- 最小输入；
- 单元素和两个元素；
- 全相等、严格递增、严格递减；
- 答案在最左、最右或不存在；
- 极值、负数、零和潜在溢出；
- 多个最优答案；
- 结构退化：链状树、完全图、孤立点等。

有朴素解时，优先做随机对拍：

```text
repeat many times:
    生成一个足够小的随机输入
    x = brute_force(input)
    y = optimized(input)
    if x != y:
        输出输入并停止
```

对拍验证实现一致性，但不能替代证明：两个程序也可能共享同一个错误假设。

## 8. 复盘成可迁移的知识

一篇高质量复盘应该能回答：

1. 最关键的识别信号是什么？
2. 暴力解的瓶颈是什么？
3. 优化利用了哪条结构性质？
4. 正确性依赖哪个不变量或证明？
5. 哪些边界最容易写错？
6. 条件改变后，算法在哪里失效？
7. 与哪些题型、数据结构或定理相连？

## 多个最优解怎么选

时间复杂度相同不代表学习价值相同。按以下顺序比较：

1. **正确性是否容易证明**；
2. **边界是否统一、实现是否稳定**；
3. **额外空间和常数是否满足约束**；
4. **能否自然扩展到追问**；
5. **是否体现一个值得复用的模型**。

推荐记住“最稳定、最可泛化”的主解法，同时理解其他最优解的适用边界。例如静态有序数组查边界，优先掌握半开区间二分；若题目扩展为动态插入，再转向平衡树而不是强行套二分。

## 一页式检查清单

- [ ] 我能用一句话描述输入、输出和核心约束。
- [ ] 我写出了朴素解及完整复杂度。
- [ ] 我指出了真正的性能瓶颈。
- [ ] 每次优化都对应一条可解释的结构性质。
- [ ] 我能说明最优解为什么正确。
- [ ] 区间、状态、编号和整数范围定义一致。
- [ ] 我测试了最小值、极值、重复值和无解情况。
- [ ] 我知道至少一个条件变化会让当前方法失效。
