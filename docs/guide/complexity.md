# 复杂度分析

复杂度描述输入规模增长时，算法消耗如何增长。它用于排除不可能通过的方案，也用于比较两种实现的可扩展性；它不是精确的运行时间预测。

## 渐进记号

- $O(f(n))$：增长率的渐进上界，算法分析中最常用；
- $\Omega(f(n))$：渐进下界；
- $\Theta(f(n))$：上下界同阶；
- $o(f(n))$：严格低阶。

若 $T(n)=3n^2+20n+7$，则 $T(n)=\Theta(n^2)$。常数和低阶项在渐进分析中被省略，但在真实比赛中仍会影响能否通过。

## 数据范围与常见上限

下表是 C++ 中简单操作的经验起点，不是判题机承诺。

| $n$ 的量级 | 候选复杂度 | 常见模型 |
| ---: | --- | --- |
| $n\le 10$ | $O(n!)$ | 全排列、暴力搜索 |
| $n\le 25$ | $O(2^n)$ | 子集枚举、状态压缩 |
| $n\le 40$ | $O(2^{n/2})$ | Meet-in-the-middle |
| $n\le 500$ | $O(n^3)$ | Floyd、区间 DP |
| $n\le 5000$ | $O(n^2)$ | 二维 DP、枚举数对 |
| $n\le 2\times10^5$ | $O(n\log n)$ | 排序、树状数组、线段树 |
| $n\le 10^7$ | $O(n)$ | 线性扫描、筛法 |
| $n$ 极大 | $O(\log n)$、$O(1)$ | 二分、快速幂、数学公式 |

判断时还要乘上测试组数 $T$，并考虑每次操作是否包含哈希、字符串比较、大整数或高常数的数据结构。

## 常见增长率

$$
O(1) < O(\log n) < O(\sqrt n) < O(n) < O(n\log n) < O(n^2) < O(2^n) < O(n!)
$$

当 $n=2\times10^5$ 时，$n\log_2 n$ 约为 $3.5\times10^6$，而 $n^2=4\times10^{10}$。这解释了为什么一次排序通常可行，枚举所有数对通常不可行。

## 如何计算时间复杂度

### 顺序执行：相加后取主项

$$
O(n)+O(n\log n)+O(n^2)=O(n^2)
$$

### 嵌套执行：相乘

外层 $n$ 次、内层每次 $n$ 次，得到 $O(n^2)$。如果内层次数依赖外层，应求和：

$$
\sum_{i=1}^{n}i=\frac{n(n+1)}{2}=\Theta(n^2)
$$

### 每次规模减半：对数

若每一步把问题规模从 $n$ 变为 $n/2$，经过 $k$ 步后为 $n/2^k$。令其等于 $1$，得到 $k=\log_2 n$。

### 分治：递归树

归并排序满足

$$
T(n)=2T(n/2)+O(n)
$$

递归树共 $O(\log n)$ 层，每层总代价 $O(n)$，所以总复杂度 $O(n\log n)$。

## 均摊复杂度

单次操作可能很贵，但一串操作的平均成本很低。例如动态数组扩容时会复制全部元素，但容量按倍数增长：

$$
1+2+4+\cdots+2^k<2^{k+1}=O(n)
$$

因此连续 $n$ 次 `push_back` 总成本是 $O(n)$，单次均摊 $O(1)$。均摊不是概率平均；它对任意操作序列都给出整体上界。

## 空间复杂度

额外空间通常不计输入本身，但要计：

- 辅助数组和容器容量；
- 递归栈深度；
- 图的边存储；
- DP 状态；
- 隐式复制和临时对象。

常见估算：`int` 通常 4 字节，`long long` 通常 8 字节。$10^7$ 个 `int` 约占 40 MB；邻接表还包含容器和分配开销，不能只按边权字段估算。

!!! warning "递归也是空间"

    深度为 $n$ 的 DFS 即使没有显式辅助数组，也可能使用 $O(n)$ 调用栈，并在链状图上造成栈溢出。

## 伪多项式复杂度

背包的 $O(nW)$ 对物品数 $n$ 和容量数值 $W$ 是多项式，但对输入位数 $\log W$ 不是多项式，因此称为伪多项式。当 $W$ 很大时，这类算法仍不可行。

## 分析检查清单

- 输入规模到底是点数、边数、值域还是字符串总长度？
- 多组测试的规模是分别受限，还是总和受限？
- 哈希操作的 $O(1)$ 是期望复杂度还是最坏复杂度？
- 排序比较是否为 $O(1)$，还是会比较长字符串？
- 递归深度和容器常数是否会触及内存限制？
- `long long` 是否足以容纳中间结果，而不只是最终答案？
