# 区间动态规划：从两端选择到合并顺序

当每次操作缩短一个连续区间，或答案由两个更短区间合并而来时，状态通常应直接描述区间。关键是明确 `dp[l][r]` 的行动者、目标与边界，而不是先背三重循环。

## 识别信号

常见信号包括：

- 每次只能取左端或右端；
- 最后一步在某个位置切分区间；
- 合并相邻段的代价依赖段边界；
- 回文、括号或矩阵链问题只依赖内部区间；
- 同一个 `[l,r]` 会从不同操作序列重复到达。

朴素递归往往已经写出了正确转移，只是重复计算相同区间。先把递归参数解释成状态，再决定记忆化或递推顺序。

## 博弈状态：保存当前行动者的净优势

两人轮流从两端取数时，若状态保存“玩家 1 的最高分”，还需要额外记录轮到谁。更小的状态是：

> $dp[l][r]$ 表示轮到行动者面对区间 $[l,r]$ 时，相对另一人的最大净优势。

取左端后，角色交换，因此子问题优势属于对手：

$$
dp[l][r]=\max\bigl(a_l-dp[l+1][r],\ a_r-dp[l][r-1]\bigr).
$$

减号同时表达了零和博弈与轮次切换，不必额外增加玩家维度。

## 递推顺序来自依赖

长度为 1 的区间是初值。更长区间依赖长度少 1 的两个状态，因此可以：

1. 按区间长度从短到长；
2. 或按右端点递增、左端点递减。

第二种顺序便于压缩空间。用一维 `dp[left]` 表示当前右端点下的答案时：

- 更新前的 `dp[left]` 仍是 `dp[left][right - 1]`；
- 已更新的 `dp[left + 1]` 是 `dp[left + 1][right]`。

因此 `left` 必须从右向左。反向循环会把两个依赖都变成本轮新值，悄悄改变状态语义。

## 切分型区间 DP

另一类区间题不是删除端点，而是枚举最后一次切分或最后被处理的位置：

$$
dp[l][r]=\operatorname{opt}_{l\le k\le r}
\bigl(dp[l][k-1]+dp[k+1][r]+cost(l,k,r)\bigr).
$$

这类状态通常有 $O(n^2)$ 个，每个状态枚举 $O(n)$ 个切分点，总时间 $O(n^3)$。优化前先判断：

- `cost` 是否可用前缀和常数计算；
- 最优切分点是否具有单调性；
- 是否满足四边形不等式或可做 Knuth 优化；
- 输出规模或约束是否其实允许立方复杂度。

## 数值、方案与计数需要不同状态

- 只求最优值：可滚动压缩；
- 恢复一组方案：保留每个区间的选择或重新分治恢复；
- 统计最优方案数：同时维护最优值与达到它的计数；
- 字典序最小方案：平局时的决策规则必须进入状态或恢复过程。

空间压缩不会免费保留所有前驱信息。先明确输出契约，再决定是否值得压缩。

## 易错检查

1. 区间是闭区间还是半开区间？
2. 空区间与单元素区间分别是什么语义？
3. 轮次切换是否通过减号、最小化或显式玩家维度表达？
4. 循环顺序是否保证依赖仍是旧状态？
5. 平局算成功还是失败？
6. 总和与差值是否可能超出 32 位整数？
