# 字符串动态规划：前缀可达与模式匹配

字符串动态规划常把“怎样切分或匹配整串”改写为“哪些前缀已经合法”。状态维度取决于未来还需要知道什么：固定字典切分只需记文本前缀，模式自身也会消耗字符时则要同时记录文本与模式前缀。

## 一维前缀可达：切分点形成 DAG

定义 `reachable[i]` 表示前 $i$ 个字符能否由合法单词拼成。若 `reachable[i]` 为真，且子串 `s[i..j)` 在字典中，就有一条从 $i$ 到 $j$ 的有向边。所有边都向更大的下标前进，因此状态图天然是 DAG。

朴素转移会对每个切分点枚举终点并构造子串。把字典建成 Trie 后，只从可达位置沿原串向后走：路径不存在时立即停止，走到单词终点时标记新的可达前缀。这样既避免重复分配子串，也让最长单词长度成为清楚的扫描上界。

若要恢复一种切分，只需在首次到达 `j` 时保存前驱 `i`；若要求方案数，把布尔或改成求和；若词典会在线更新，静态 Trie 不再足够，应结合增量 Trie、自动机或离线批处理重新评估复杂度。

## 二维前缀状态：文本和模式共同前进

当模式中的一个符号可能匹配零个或多个文本字符时，只记录文本位置会丢失“模式已经处理到哪里”。定义 `dp[i][j]` 表示文本前 $i$ 个字符与模式前 $j$ 个字符能否完全匹配。

普通字符或点号只可能同时消耗一个字符；星号修饰前一原子时，最后一步分为两类：

- 匹配零次：丢弃模式末尾的“原子 + 星号”；
- 匹配至少一次：当前字符先由该原子匹配，模式仍停在同一位置继续接收字符。

这两个分支按最后一步完备划分所有合法匹配。空文本边界必须单独初始化，因为只有成对出现的 `x*` 能连续匹配空串。

## 状态选择边界

先判断约束改变了哪一种未来信息：

- 只问能否由固定词典切分：一维前缀可达；
- 同时消耗文本和模式：二维前缀匹配；
- 通配规则可以编译成有限状态自动机：状态可改为“文本位置 + 自动机状态”；
- 需要全部方案或字典序最小方案：在同一 DAG 上增加计数或父指针；
- 需要大量文本匹配同一模式：先编译模式，避免对每个文本重复建立转移结构。

## 正确性与实现检查

1. 状态究竟表示“完整匹配前缀”还是“以当前位置结尾的局部匹配”？
2. 每个转移是否严格推进至少一个维度，或能证明不会形成未处理自环？
3. 空串、空模式与可重复零次的结构是否正确初始化？
4. 枚举切分点时是否只从可达前缀出发？
5. 字符串切片是否造成隐藏的额外复制？
6. 空间压缩后，当前行是否会覆盖仍需读取的上一行状态？
